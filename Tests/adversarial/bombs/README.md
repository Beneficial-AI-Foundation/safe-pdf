# Decompression-bomb corpus (task 3.6a, milestone M3)

Plan.md §6 Phase 3 (M3: "decompression-bomb suite (nested streams, 10⁶:1 ratios) all rejected
within limits"), §4 S3 (decoded output ≤ limit, or an error), §7 item 3 ("All must fail
*fast and cleanly*").

**Do not open these files in any PDF viewer**: they inflate to hundreds of megabytes or
gigabytes. They are inputs to the verified core only (`Tests/Bombs.lean`).

Generated by `python3 -I Tests/adversarial/bombs/generate.py` (stdlib only: `zlib`, `struct`,
`hashlib`; deterministic). `--check` regenerates everything in memory and compares it
byte-for-byte with the files here (exit 1 on a mismatch, unexpected files included). The exact
Flate bytes depend on the zlib library Python links; a `--check` failure on another machine
prints the zlib version. `MANIFEST` lists `sha256  size  name` per file. Do not hand-edit;
edit the generator and regenerate.

## Layout

For each raw stream `NAME`: `NAME.bin` (encoded data), `NAME.dict` (its stream dictionary,
PDF text, no `/Length`) and `NAME.pdf` (one page whose `/Contents`, object 4, is that stream;
not for the two `control-flate-256m*` streams). Three bombs (and `objstm-two.pdf`, the document-budget control) exist only as PDFs because
they live in the file structure.
