# Adversarial seed corpus

Hand-built PDFs with **malicious structure** in the style of Bogk & Schöpl,
["Formal verification of a PDF parser: a termination argument"](https://ieee-security.org/TC/SPW2014/papers/5103a198.PDF)
(LangSec 2014; IEEE record <https://ieeexplore.ieee.org/document/6957304/>), who showed
that crafted xref cycles hang real readers. Plan.md §2 (row 1), §5.2, §6 Phase 2 M2, §7 item 3.

**Do not open these files in any PDF viewer**; they are designed to hang or crash readers.
They are only inputs to the verified core and the fuzzer.

Generated by `python3 -I Tests/adversarial/generate.py` (stdlib only, deterministic).
`--check` re-reads each file and verifies that `startxref` points at `xref` (or the xref stream
object) and that every in-use xref entry points at `N G obj`. Each file is otherwise well-formed:
the only defect is the one listed. Do not hand-edit the PDFs; edit the generator and regenerate.

Expected outcome for every attack file: **rejected with a structured `Error`, in bounded time**
(no hang, no stack overflow, no unbounded memory). `minimal-valid.pdf` must be **accepted**.
Property names are from Plan.md §3 (S2 totality, S3 bounded resources); measures from §5.2.
